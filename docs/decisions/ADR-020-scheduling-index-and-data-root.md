# ADR-020：活动调度索引与显式数据目录

> Status: DECISION
> Date: 2026-11-10

## 原因（Context）

批量 API 调用在历史任务超过千条后，反复在共享调度锁内校验 task/result 等全部记录，导致 5 秒队列超时。远端样本 1,929 条的一轮校验约 1.19 秒。仅增加锁等待时间不能消除这个开销。持久化 DATA_DIR 还覆盖了调用方的显式环境变量，阻止独立批次隔离数据及 worker 配额。

## 决定（Decision）

1. TaskStore 在 `.tasks/.scheduling/` 保存活动任务 ID 标记。它只提供候选集合，调度状态仍以每个任务的原子 status、task、workspace、result 和 attempt 记录为准。Manager 每次重新验证候选，不缓存任务状态；queued、running、cleanup_unverified 及损坏记录不得被遗漏。
2. 每个状态写入在原状态锁内先登记候选，再原子提交状态；登记失败则不提交。健康终态只有在同一状态锁内重新校验后才能撤销标记。崩溃允许留下多余候选，不允许先删候选再提交状态。续作和清理失败会重新登记；结果和历史查询路径不变。
3. 首次使用旧数据目录时，全量校验并迁移一次，在独立初始化锁内分批让出事件循环，不持有共享调度锁；初始化成功后才发布版本标记。损坏/缺失的版本标记触发重新迁移，已有候选不清空。旧版 worker 可以完成已登记的运行任务；同一数据目录的所有 Manager 必须一起升级并重连，不能混用不会登记候选的旧版 Manager。不得静默热替换正在运行的旧 Manager。
4. 健康、已验证清理的历史终态不再参与每轮调度校验；后续手工编辑这些记录不作为恢复/调度入口，点查仍校验其记录。活动记录损坏继续保留目录占用；范围未知时阻止新调度。不删除或归档用户历史，不增加超时、不放松工作区互斥、不自动重试 provider 失败。
5. 仅对非空的显式 `ZCODE_BRIDGE_DATA_DIR`，环境变量优先于持久化设置，仍要求绝对路径。空值不清除持久化设置；其它键保留配置优先。Host、worker 和预约 runner 使用相同解析规则。不修改用户的持久化配置或搬迁旧任务；新的目录是独立任务库，拥有独立锁和 worker 并发名额。
6. 按用户要求，同一数据目录的 worker 并发默认值和可配置上限均由 8 调整为 20；有效范围为 1–20。普通入口、预约 runner 和 Windows 配置入口一致；已有配置中的较小值继续生效，重叠执行路径仍串行。

## 取舍（Rationale / Consequences）

文件候选登记复用现有 task 锁与原子状态，不引入数据库依赖。它将完整历史读取集中在首次迁移，代价是写入时多一个小标记及升级时需统一重连；不再支持通过手工改健康终态历史文件影响调度。真正活动任务及损坏候选的成本仍随其数量增长，不承诺任意负载下零超时。

## 验收

覆盖旧库迁移、热路径不读取健康历史、跨 Manager 提交/续作、worker 清理锁存、写前登记失败、终态删除与续作竞争、损坏记录和重建。用独立进程、千级合成历史和无模型任务验证并发提交及结果读取；明确冷迁移与热路径耗时，保留实际未运行边界。DATA_DIR 覆盖须验证两个宿主、子进程入口与其它配置的原优先级。
