## 同库升级与任务

部署协调器先获取已有的共享 Manager 锁暂停调度，再替换所有共用数据库的入口、关闭旧 Bridge 连接并迁移索引，最后释放锁。部署前用临时 HOME 和合成数据库演练完整流程，通过后才操作实际安装。

本机关闭 5 个旧 Bridge Manager，远端关闭 11 个。远端其中 1 个未在 3 秒内响应 SIGTERM，按已验证的进程身份发送 SIGKILL；后验只留下等待宿主回收的 Z 状态记录，没有旧 Manager 继续执行。没有重启或终止 Codex、Claude 主进程，也没有向 detached worker 发送信号。升级前后 worker 数量随用户任务执行变化，没有把自然结束算作部署取消。

三个原有任务库已建立版本 1 的调度索引；迁移完成时，活动候选数分别为本机 0、远端 Codex 0、远端 Claude 5。候选包含当时运行或排队的记录，后续仍由正常恢复逻辑重新校验；历史任务和数据目录没有删除或搬迁。实际后验检查中部署锁已释放。检测时没有运行中的预约 runner，本次未验证活动 runner 的原位升级。

## 验证范围

四个入口分别使用临时 HOME、独立数据目录和故意不存在的 provider 文件启动，只发送 MCP 初始化、工具枚举和 doctor 请求。三处插件按实际安装 bundle 启动；独立 Claude 服务保留真实 startBridge 适配器，仅将配置与数据路径换成临时目录，没有执行生产代理 wrapper。

全部检查通过：工具集合、raw/minimal、Kimi 及其 yolo 参数、task/continue 图片附件 schema；运行构建等于部署前计算的提交产物构建，磁盘状态为 same，reconnect_required=false；Node、Git、ZCode runtime 检查正常。隔离配置没有并发覆盖值，四个入口的启动日志均显示默认 20；实际生产配置另外只读确认显式 20 和 yolo。provider_config=error 是故意缺少临时凭据的预期结果，不是生产 provider 可用性结论。

首轮本机探针误填了不存在的 runtime 路径，在启动插件前失败；改用实际配置路径后通过。额外退出检查最初仅按 /proc 记录存在判断，复核进程状态后确认剩余记录已退出。上述检查失败没有计为通过。

此前受测代码的 Linux Node 22 全量结果为 694 项：690 通过、0 失败、4 项平台条件跳过；Node 24 定向 87/87，clean-entrypoints 6/6。typecheck、build、validate:plugin 和差异检查通过。本次部署后的检查只验证安装加载与接口，没有重跑真实模型、20 路模型吞吐或 Windows/macOS 真机。

## 使用边界

当前聊天需要重新连接 MCP；若宿主不自动重连，重新打开聊天或重启相应 Codex / Claude 会话。磁盘替换不会热更新已经加载的进程。旧 Manager 与新版不能共用同一任务库；回退后再次升级的索引重建步骤见[开发报告](2026-11-10-batch-scheduling-and-data-root.md#安装边界)。

本轮保留生产数据目录。慢共享盘的突发写入排队超时仍有实测失败，不能将索引优化或上限 20 解读为任意存储零超时；需要隔离批次时可使用显式绝对 DATA_DIR，但本次没有自动搬迁生产数据。相同或重叠执行目录仍串行。
