# Kimi API 模式真实验证与修复

> Status: RESEARCH
> Date: 2026-11-10
> Verified against: 1878b33734b27070da14cd283b7a9e89acd94cae
> Scope: Linux 本机及 SSH 远端，四个实际安装入口；不扩展到其他模型或平台。

用户确认额度恢复后执行真实模型测试，发现并修复两处离线 fixture 未覆盖的问题。没有修改 Kimi/ZCode 默认模型、全局工具配置或原生默认系统提示。

## 发现与修复

- 初始 `/tools` 枚举先于异步 MCP 加载，图片还会晚注册 `ReadMediaFile`。旧 minimal 本机首轮向模型暴露 208 个工具，续作 207 个；默认对照为 234 个。“没有调用工具”不能证明工具定义已移出预填。现在每次 prompt 除枚举名称外，追加原生 `mcp__*` 名称模式及 `ReadMediaFile`，覆盖已观察的晚注册来源；实际工具面由原生 `llm.tools_snapshot` 与请求引用独立核对。
- 原生 GET session 的 usage 是索引零占位，不能当作实际消耗。现在从 `snapshot.session.usage` 获取会话累计数值，保留非缓存 input_tokens / output_tokens，并把 cache_read_tokens 映射为 cached_input_tokens。续作累计值已与原生逐轮 usage.record 核对；不从日志驱动生命周期，不用缺失值估算 0。

决策与版本边界见 [ADR-019](../decisions/ADR-019-kimi-late-tools-and-usage.md)。未知未来内置工具仍需实测，技能目录及其他原生基础上下文仍可能存在。

## 必须保留的数据失败

远端 OCR 测试首轮将合成代码 `CM9BZ` 读成 `CN9BZ`，续作把新图 `2MAM4` 读成 `2NAM4`。两轮模型原生完成、原文 JSON 合法、工具数 0、同 session 和清理均正常，但精确数据验收均失败；原生媒体副本与两张源图字节一致。没有把这两次错误算作准确率通过，没有原样重试到通过。

随后另设颜色/数量测试验证传图和旧图记忆，仍保留独立的 OCR 失败记录。该结果不证明精简模式对业务准确率无损；调用方必须校验数据，`completed` 不能替代验收。

## 回归与部署

- Kimi 定向离线回归 28/28，通过晚注册工具、同会话禁用、默认兼容、索引零值/快照真实值、缓存分列、附图、权限、额度及清理分支。
- 完整回归最后一轮 676 项：672 通过、4 跳过、0 失败。跳过的是 Windows 启动钩子、两个 Windows 进程树语义子例和非 Linux 调度行为；本轮未验证这些平台。
- 首次完整回归有 1 次调度超时用例时序失败；原用例单独重跑通过，完整重跑也通过。没有修改该调度实现或删除断言，首次日志保留。
- typecheck、build、validate:plugin、clean-entrypoints 6/6、git diff --check 通过。
- 功能提交 1878b33 已推送；本机 Codex 插件、远端 Codex/Claude 插件各 30 个管理文件及独立 Claude core 166 个文件完成备份、替换和字节核对，用户配置/代理包装器保持原样，未终止已有用户会话。
- 测试启动的临时 Bridge 连接与 Kimi 进程树均正常结束。已运行宿主不会热加载，需重连 MCP 或新开会话。

初次远端探针因测试 PATH 未带 Kimi 而在模型调用前 spawn_failed；补齐测试环境后继续。另一次新增颜色用例漏传两张合成图，被附件校验在模型调用前拒绝，补齐后以新用例运行。一次候选验证受既有共享任务根影响，由旧 worker 接走；候选验收改为独立设置/数据根，正式安装再单独复测。这些探针错误均保留，未当作产品通过证据。
