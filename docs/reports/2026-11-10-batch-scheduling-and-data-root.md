# 批量调度、数据目录与并发上限修复

> Status: RESEARCH
> Date: 2026-11-10
> Baseline: 01748cd0d872c49703ee771dd7382f05065119a6
> Scope: ADR-020 工作树验证；测试阶段生产安装未替换，后续部署另记

## 已核实的问题

远端反馈更新集中在两条：千级历史下重复校验引起共享调度锁排队超时；持久化 DATA_DIR 覆盖显式环境变量，导致批次不能隔离任务库。实际生产目录只读抽样时有 1,929 条任务，枚举约 59 ms，校验 status/task/workspace/result/attempt 约 1,194 ms。扫描中曾观察到一个任务目录随后完全消失，不能据此断言它持续损坏。

原报告中的 raw 输出和 minimal 工具面已由 ADR-017/019 处理；同一或嵌套执行目录串行是现有保护，不能以 allowed_paths 为空当作只读证明。更新安装文件也不会更新已经加载的 MCP 进程。

本轮安全投影的最近 10 条原生失败都带 code=1301、statusCode=400、retryable=false、category=content_filter，属于上游内容过滤拒绝，不能当作额度或网络错误自动重试。ADR-018 的 provider_error 已能返回这些信息，不需要再改错误分类，也没有尝试绕过过滤。

## 改动

- 为活动任务登记候选标记；状态发布前先登记，登记失败则不改状态。健康终态只在任务状态锁内重新校验后撤销候选；续作、清理失败和记录损坏不能因此释放占用。
- 历史库首次迁移在单独初始化锁内执行，定期让出事件循环，不占用共享调度锁。热路径仍读取实际活动状态，不读取健康历史终态，不删除历史任务。
- 只有非空显式 ZCODE_BRIDGE_DATA_DIR 覆盖同一字段的持久化设置，要求绝对路径；其它设置和代理启动链保持原有优先级。空值不清除设置，不搬迁数据。
- 按用户要求将默认并发与可配置上限改成 20，范围 1–20；普通入口、预约 runner 与 Windows 配置入口一致。已有较小配置继续生效；同一或重叠执行路径仍串行。

## 验证记录

最终 Linux Node 22.22.2 完整回归：694 项，690 通过、0 失败、4 项平台条件跳过。跳过项是 Windows 启动 hook、两项 Windows 进程树语义和非 Linux 预约拒绝分支，没有计作通过。Node 24.22.1 受影响七套件 87/87，clean-entrypoints 6/6；typecheck、build、validate:plugin、diff 检查通过，三个提交用 bundle 已同步。

专项覆盖旧库迁移、活动状态重新校验、写前登记失败、未知范围保守占用、清理锁存、同会话续作、版本标记重建，以及目录在迁移前/中被删除。真实子进程制造终态撤销与续作竞争；删除编译副本中的撤销锁后，该测试按预期失败，恢复后通过。实际旧版 TaskStore 的 worker 提交可被新版恢复并保留结果，冷迁移不占用共享 manager 锁。默认/显式 20 都验证了前 20 个不同目录任务运行、第 21 个排队、释放名额后继续；21 及非整数配置拒绝。

两个宿主的实际远端保存配置做只读 old/new 解析对照：旧版覆盖批次目录，新版保留显式目录；其它已知设置相同，原配置字节未变。另用真实 stdio 子进程验证默认 Codex 和自定义 Claude 入口只创建选定数据库，不访问保存的任务库。代理 wrapper 不会重设 DATA_DIR。

压力测试使用 2,000 条合成历史、两个独立 Manager 进程、独立工作区和模拟 worker，不调用模型。每进程各做三批，批量大小如下；统计接收/完成数，失败提交后查询产生的 TASK_NOT_FOUND 不另算调度故障。

| 环境及每进程批量 | 基线接收并完成 | 候选接收并完成 | 基线 → 候选提交 P95 |
|---|---:|---:|---:|
| 远端共享盘，8（合计 48） | 18/48 | 40/48 | 36,581 → 6,734 ms |
| 远端本地盘，20（合计 120） | 120/120 | 120/120 | 5,170 → 176 ms |
| 本机本地目录，20（合计 120） | 120/120 | 120/120 | 3,974 → 967 ms |

远端本地盘候选 120/120 无错误，最大提交 196 ms、状态查询 P95 0.26 ms。三个热恢复周期对历史的 readTask 次数由 6,000 变为 0，约 129–132 ms/轮变为 0.23–0.27 ms/轮。冷迁移仍须全量读历史：该盘约 181 ms，共享盘约 13 秒。本机候选同样零错误。对照也包含默认并发从 8 到 20 的改动，延迟收益不单独归因于索引；热路径历史读取计数是独立验证。

共享盘的原始写入瓶颈仍在：候选 2×8 有 8 次排队超时；更强的 2×20 突发测试只有 46/120 被接收，其余 74 次超时。因此不能声称共享盘已达零超时。样本测得状态写入平均约 55 ms；实测文件系统分别为共享 dpc 与本地 overlay。索引移除反复历史读取，显式目录修复允许批次选用本地存储，两者不能替代存储吞吐。5 秒背压、32 项进程队列和同 task_id 重试合同保持不变，不增加超时掩盖问题。

此前失败的共享盘候选、旧测试断言和沙箱子进程 EPERM 记录均保留在本地诊断材料，没有计为通过；最终完整回归是在可正常执行隔离子进程的独立监督单元中完成。

## 安装边界

本轮只在独立工作树和远端诊断目录测试，没有修改生产任务、配置或已安装服务。共享同一任务库的所有 Manager 必须一起升级并重连；旧 Manager 不会为新任务登记候选，不能与新版混用。旧版 detached worker 可以完成迁移时已登记的运行任务，本轮有兼容性检查。若退回旧 Manager 写过任务，再次升级前须在所有 Manager 停止时移除 .tasks/.scheduling/.ready.json，以强制重新迁移；不要清除用户历史。

已有保存的并发值不会被代码默认值覆盖。要使实际安装采用 20，需将相应宿主 runtime-config.json 的 ZCODE_BRIDGE_MAX_CONCURRENT_WORKERS 改为字符串 "20"，在统一升级后重连。当前旧版不接受 20，不应先单独修改生产配置。

Windows/macOS 真机、真实执行器的 20 路吞吐和额度行为未运行；本轮的压力测试检验调度持久化与结果读取，不推断模型吞吐或数据质量。
